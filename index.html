PLC Programming

For this project, our team was assigned to design a program to handle a pick-and-place operation on the PLC bearing station. The task involves moving the equipment's arm from its initial middle position to the bearing, picking it up, and transferring it to a second position where the bearing is placed. Afterward, the arm smoothly returns to its starting point. If no bearing is detected, the arm stays put, even when the start button is pressed.

Additionally, the arm can shift from the middle to the back position if a bearing is detected there, pick it up, and move it to the front before resetting to the middle. At any time, pressing the stop button halts the operation, which can be resumed by pressing start. In manual mode, users need to press the start button for each step of the process.

ABB Robot
Programming

Pick-and-place operations are widely used in automated industrial processes. In this project, a four-person team developed a visually guided pick-and-place system using a robotic manipulator. The goal was to have the robot autonomously identify and manipulate different objects based on their size and position, ultimately rearranging them to form the word "HI."

The task involved recognizing three rectangular bars of the same length and one shorter bar placed in arbitrary positions. The robot had to accurately determine the size, position, and orientation of each bar and then rearrange them to spell out "HI." This required precise identification and manipulation to meet the projects goal.

The project was divided into several key tasks. First, forward and inverse kinematics were derived theoretically and implemented in MATLAB. The team then simulated the robot’s motion using the Robotics Toolbox. STL files of each part of the ABB IRB120 robot were extracted and combined in MATLAB to create a 3D model using robot.plot3d. In addition to modeling, image processing techniques were applied in MATLAB to distinguish between the different sizes of the bars and to locate their centroids. A RAPID program was written to simulate the robot’s pick-and-place operation based on this information. Finally, the position of the blocks in the target area was determined in MATLAB, and a virtual work environment was created in Robot Studio for further simulation and testing.

The Hand-Eye Coordination project, designed to detect objects of different sizes and rearrange them to form the word "HI," was a success. Two pick-and-place scenarios were implemented: one where no items were present in the assembly zone and another where objects were already within it. In the second scenario, the robot first moved the objects aside before rearranging them in the correct order. In the first scenario, the robot simply picked and placed the items as they did not interfere with the assembly area.

Microcontroller-Based Home Security Lighting System

This project proposes a microcontroller-controlled home security lighting system using solar-powered streetlights, a LUX (light) sensor, and a PIR motion sensor to automate lighting and alarms for improved home security.

System Overview
  • Solar security lights automatically turn on at night and off during the day based on ambient light measured by a LUX sensor.
  • A microcontroller processes sensor data and controls lights using thresholds with hysteresis to prevent frequent switching.
  • A PIR motion sensor detects movement (via temperature changes) to activate additional lighting and an alarm.
  • Users can adjust sensor sensitivity (LUX and temperature thresholds) via control buttons.
  • LEDs emulate security lights, motion lights, and alarm indicators.
Key Features
  • LUX sensor (ADC channel 14): controls night/day lighting with adjustable sensitivity.
  • PIR sensor (ADC channel 15): triggers motion lights and alarm with adjustable temperature thresholds.
  • Hysteresis (±2 units): ensures stable operation.
  • Continuous monitoring using an infinite loop with real-time console feedback.
Implementation Highlights
  • Uses GPIO ports for inputs (buttons, sensors) and outputs (lights, alarms)
  • ADC with 10-bit resolution for accurate sensor readings.
  • Software includes sensor scaling, delay functions, and clear ON/OFF logic.
  • Results demonstrate correct independent and combined operation of security lights and alarms, with adjustable sensitivity.
Advantages
  • Improved security through motion detection and alarms
  • Cost-effective components (PIR sensors, LEDs).
  • Reliable during power outages.
  • Environmentally friendly and renewable.
Disadvantages
  • High initial cost for solar equipment.
  • Dependence on sunlight for optimal charging.
  • False alarms due to sensor sensitivity (e.g., animals triggering motion).

Microcontroller-Based Automatic Water Tank Level Control System

This project proposes a microcontroller-controlled water tank system that uses ultrasonic sensors, GPIO pins, an FTM timer, and an LCD/console display to automatically turn a water pump on and off based on water levels.

System Overview
  • Two ultrasonic sensors monitor the low and high water marks.
  • When water falls below the low mark, the pump is turned on; it turns off when water rises above the high mark.
  • The FTM (FlexTimer Module) input capture records the time taken to fill the tank.
  • Warnings and pump status are displayed via LCD or Termite console.
  • GPIO pins emulate water level indicators, while ADC and timers handle sensor readings.
Implementation Highlights
  • Ultrasonic sensors interface with microcontroller via FTM channels for water level detection.
  • Pump control logic implemented in an ISR to respond to sensor signals in real-time.

Electronic Music Box Using SysTick and PIT Timers

This project aimed to design an electronic music box using a microcontroller by combining the Programmable Interrupt Timer (PIT) for tone generation and the SysTick timer for controlling note duration.

The PIT module generates square-wave tones by converting user-defined frequencies into timer tick intervals, where higher frequencies produce higher-pitched sounds. The SysTick timer is used to accurately control how long each tone plays by counting clock ticks and triggering interrupts after a specified duration.

A reusable playTone() function was developed to play a specific frequency for a defined duration using PIT for sound generation and SysTick for timing. This function was first tested with single tones, then extended to play a full melody.

In the second phase, the “Happy Birthday” melody was implemented by storing note frequencies and durations in arrays and looping through them to generate the song. In the final phase, song lyrics were printed in real time to a serial terminal alongside the music by synchronizing text output with each note.

VHDL Traffic Light Control System

This project involved designing and synthesising a traffic light control system in VHDL, targeting a CoolRunner2 CPLD using Xilinx ISE.

The system manages traffic and pedestrian lights across East-West (EW) and North-South (NS) lanes through three interconnected modules, achieving a clean synthesis with 0 errors and 0 warnings.


System Overview
  • A 10-state Finite State Machine controls light sequencing across EW and NS lanes, handling vehicles, pedestrians, and simultaneous inputs from both directions.
  • An Input Sync Memory module clock-synchronises car sensor inputs and latches pedestrian button presses, retaining them until the state machine issues a clear signal, ensuring no button press is missed.
  • The Traffic Top Level module combines both sub-modules into a single integrated system with 6 inputs and full light, LED counter, and sync outputs.
  • Traffic lights are encoded as 2-bit values: 00 = Red, 01 = Amber, 10 = Green, 11 = Both traffic and pedestrian lights green.
Key Features
  • 10-state, 26-transition FSM with automatic one-hot encoding applied by Xilinx ISE during synthesis.
  • Synchronous state transitions on rising clock edge with asynchronous reset to EWGreen_Idle.
  • Moore-style outputs for traffic light control; Mealy-style outputs for timer management.
  • 4-bit counter with defined constants for 2 s, 3 s, and 10 s state delays.
  • Priority handling: the system serves whichever direction (or pedestrian) triggers first, then cycles back for the second.
Implementation Highlights
  • Three VHDL modules designed, implemented, and integrated: Input Sync Memory, State Machine, and Traffic Top Level.
  • Pedestrian button memory implemented using a synchronous latch, cleared only when the corresponding pedestrian green state is reached.
  • Comprehensive testbenches written and simulated covering 6+ scenarios: EW traffic only, NS traffic only, simultaneous EW/NS traffic, EW pedestrian only, NS pedestrian only, mixed pedestrian and vehicle inputs, and button-press priority ordering.
  • Synthesised for CoolRunner2 CPLDs; final design utilises 22 flip-flops, 197 logic cells, and 18 I/O buffers.
Advantages
  • Fully automated light sequencing with no manual intervention required.
  • Pedestrian button memory ensures requests are never dropped even if the button is released before the state is reached.
  • Priority-sensitive design correctly handles simultaneous inputs from both lanes..
  • Clean synthesis with zero errors and zero warnings.
Disadvantages
  • State machine tested in simulation only, no physical hardware deployment.
  • Fixed time delays (2 s, 3 s, 10 s) with no runtime adjustment capability.
  • False motion triggers are not accounted for in the current design.

The pipeline automates testing, quality analysis, security scanning, artifact versioning, and deployment with rollback support using a fully infrastructure-as-code approach.


Pipeline Overview

  • GitLab webhooks automatically trigger Jenkins CI pipelines on code push and merge requests.
  • Gradle build pipeline integrates JUnit 5, Selenium WebDriver, JaCoCo, Checkstyle, and SpotBugs.
  • SonarCloud performs automated code quality, maintainability, and reliability analysis.
  • Docker images are scanned using Hadolint and Trivy before deployment.
  • Terraform provisions two Debian 13 Azure DTL virtual machines for CI and runtime separation.
  • Nginx reverse proxy routes HTTP traffic to containerised Spring Boot services.
  • Automatic rollback mechanism restores the previous image if deployment health checks fail.

Key Features

  • Two-VM architecture separating CI infrastructure from runtime deployment environment.
  • Infrastructure-as-Code provisioning using Terraform.
  • Automated container deployment using Docker and SCP image transfer.
  • GitLab Package Registry used for versioned JAR artifact storage.
  • Automated security and static analysis integrated into CI pipeline.
  • Headless Selenium browser testing configured on Debian CI environment.
  • Reverse proxy deployment with health-check validation and rollback handling.

Implementation Highlights

  • Built and deployed a Spring Boot application using Gradle-based CI/CD workflows.
  • Implemented automated testing pyramid using unit, integration, servlet, and end-to-end tests.
  • Configured Docker containerisation and Nginx reverse proxy networking.
  • Integrated SonarCloud dashboards with JaCoCo, Checkstyle, and SpotBugs reporting.
  • Used Trivy to detect OS-level and Java dependency vulnerabilities.
  • Implemented automated deployment validation with rollback support.
  • Supported multi-user collaboration through Jenkins users and GitLab merge-request automation.

Migration Strategy

  • Proposed migrating the existing Azure DTL two-VM pipeline to a managed Google Cloud Platform architecture.
  • GitLab would trigger Cloud Build instead of Jenkins, while keeping the Gradle build and testing workflow largely unchanged.
  • Built container images would be stored in Artifact Registry and deployed to Cloud Run using revision-based deployments.
  • Nginx reverse proxy would be replaced with Cloud Load Balancer and Cloud Armor for traffic routing, TLS support, and web protection.
  • SSH keys and Jenkins credentials would be replaced with Secret Manager and Workload Identity Federation.
  • Cloud SQL would handle persistent MySQL storage, while Memorystore for Redis would support caching and session-related performance improvements.
  • The migration would be done gradually by running GCP alongside the current DTL setup, validating Cloud Run deployment, shifting traffic in stages, and decommissioning DTL after monitoring.

Advantages

  • Fully automated build, testing, and deployment workflow.
  • Improved deployment consistency through Infrastructure-as-Code.
  • Enhanced security through container scanning and isolated runtime environments.
  • Supports scalable and production-aligned deployment practices.
  • Reduces manual deployment errors and improves reliability.

Limitations

  • Brief downtime occurs during container replacement deployments.
  • Pipeline depends on Jenkins availability and GitLab webhook reliability.
  • Current deployment does not yet implement blue-green or zero-downtime deployment.
  • Cloud-native orchestration tools such as Kubernetes are not yet integrated.
